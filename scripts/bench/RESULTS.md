# Latest benchmark results

What the harness last measured. The block below is **generated** — regenerate it after a
run instead of editing it:

```bash
scripts/bench/render-results.py            # rewrite the generated block
scripts/bench/render-results.py --check    # exit 1 if it is out of date
scripts/bench/render-results.py --runs 5 --min-cells 10
```

Everything outside the markers is hand-written and survives; everything inside is
replaced, so a number edited by hand there is lost — deliberately, because a
hand-maintained number is one that goes stale without anyone noticing.

## How to read these numbers

- **A cell is `pass/total`**, judged deterministically: `cargo run` / `cargo test` decides,
  not the model's own claim. With `REPS>1` the denominator is the repetitions, so a cell
  is a pass *rate*, not an anecdote.
- **Median seconds appear only for runs with their own gateway.** A run that borrowed a
  resident model (`BENCH_GATEWAY_URL`) has contended timings — the same task measured 67 s,
  193 s and 163 s in one such run — so those runs are labelled `shared` and their seconds
  are omitted rather than printed with a caveat.
- **Do not compare across runs.** Different binaries, model sets, host load and dates. Each
  run is reported as itself; the progression of a *fixed* suite over time belongs in
  [`HISTORY.md`](HISTORY.md), which records what changed between entries.
- **No blended total.** A run mixes curated coders with probe models kept for context, and
  an average over both moves when the probe list changes rather than when anything
  improved. Read the per-model rows.
- **By-task lines matter.** `greet` is one word with no tools; `debug` is a run-read-fix
  loop. A model that clears the ladder's first rung and nothing else is a known shape
  (the 7B→27B capability cliff), not a surprise.

For what the harness is and how to run it, see [`README.md`](README.md).
