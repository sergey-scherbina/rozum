# Demo Conference — humans + models in one sandboxed space

## Overview

A **demo conference**: a polished, cross-platform **PWA** through which several
**humans** (the operator and relatives) and **three AI models** (Claude via an
agent client, the local **Qwen3.6-35B-A3B**, and the local **gpt-oss-20b**)
gather in **one shared space of many rooms**, talk together in real time, and can
**break out one-on-one**. The entire backend — every model run and every shell/file
action it performs — is confined to the existing **Seatbelt sandbox**
(`docs/specs/model-sandbox.md`). Nothing here changes the *default* meeting runtime:
the conference is an **optional layer composed on top of** the meeting daemon
(`docs/specs/agent-meetings-daemon.md`), its MCP protocol
(`docs/specs/agent-meetings-mcp.md`), and the model gateway — all of which already
exist. The operator presents a product, **`busi`**, inside the demo; this spec
leaves a defined seam for it and does not specify `busi` itself.

This spec covers the **one genuinely new capability** — a *model-participant
bridge* (a local model joining a room as a live chat participant alongside humans) —
and the **composition contract** that ties the existing pieces into the demo. The
PWA front end (`.ssc` → JS, installable) and the sandbox wrapping are owned by the
co-agent who maintains `src/meeting/web_index.html` and `src/sandbox.rs`; this spec
references their contracts and is the coordination point, not their re-design.

## Interface

### New: model-participant bridge

A long-lived process that makes a *local model* a first-class room participant.

- CLI: `rozum meetings participant --model <spec> --room <name> [--as <handle>]
  [--reply-policy <policy>] [--gateway-url <url>] [--peer <handle>...] [--persona <text>
  | --persona-file <path>]`
  - `--model <spec>` — a catalog/gateway model spec (e.g. `mlx-community:gpt-oss-20b-MXFP4-Q4`).
  - `--room <name>` — the room to join (created if absent, per daemon rules).
  - `--as <handle>` — display handle (default derived from the model, e.g. `gpt-oss`).
  - `--reply-policy <policy>` — `mention` (default) | `always` | `manual`. Governs *when*
    the model contributes. This is a **politeness policy of one participant**, never a
    room-level moderator or turn-scheduler (see Decisions; honors the global no-moderator
    invariant).
  - `--gateway-url <url>` — the local gateway serving `--model` (OpenAI `/v1`).
  - `--peer <handle>` (repeatable) — other model handles, so `always` never loops model↔model.
  - `--persona <text>` / `--persona-file <path>` — prepends WHO the model is + domain context
    to its system prompt, so it answers on-topic (e.g. about `busi`) rather than generically.
- Identity: the bridge presents a stable participant identity via the same
  `Principal`/session-token mechanism as human clients (`docs/specs/agent-meetings-*`),
  so it shows up in the roster as one participant with a fixed handle.
- Transport: the bridge is a **meeting client** — it reads the room transcript and
  `meeting.submit`s replies through the existing daemon protocol; it performs **no**
  privileged daemon operations and is **not** the single writer.
- Inference: replies are generated by calling the **existing gateway**
  (`docs/specs/api-gateway.md`) for `--model`; the bridge holds no model in-process.
- Confinement: the bridge process (and the gateway/model it drives) runs **inside the
  Seatbelt jail** (`docs/specs/model-sandbox.md`); a participant cannot touch anything
  outside the conference's path-set.

### Composition seams (existing components, referenced)

- **Meeting daemon / rooms** — unchanged. Many rooms, disk-backed, single-writer; a
  one-on-one *breakout* is simply a room with two participants.
- **PWA front end** (co-agent) — `src/meeting/web_index.html`, authored in `.ssc`
  (ScalaScript JS backend) and packaged as an installable PWA (manifest + service
  worker). Talks to rozum over the meeting daemon (rooms/messages) and, for any model
  features it surfaces, the gateway. **This spec does not define its UI.**
- **Sandbox** (co-agent) — `src/sandbox.rs` Seatbelt jail; the conference launcher wraps
  the whole backend session in it.
- **`busi` seam** — `busi` participates as either a human-operated client or a
  model-participant under a `busi` handle; the conference treats it as an ordinary
  participant. No conference code depends on `busi` internals.

## Behavior

- [x] A local model joins a room and appears in the roster as one stable-handle participant.
- [x] With `--reply-policy mention`, the model replies only when its handle is @mentioned;
      it stays silent otherwise (no spam, no turn-taking).
- [x] With `--reply-policy always`, the model may reply to any new human message; never to
      its own or another model's messages (no model↔model runaway loop).
- [ ] Two participants (any mix of human/model) in a fresh room constitute a working
      one-on-one breakout; messages there are not visible in other rooms.
- [x] Humans and models in the same room see the same transcript in arrival order; there is
      no turn expiry, round-robin, or moderator (global invariant preserved).
- [x] The bridge degrades safely: if the gateway/model is unavailable, the participant
      posts nothing (or a single `blocked:` notice) and never crashes the room.
- [ ] Every shell/file action any model performs is denied outside the conference path-set
      (Seatbelt escape test, per `model-sandbox.md`). *(co-agent-owned sandbox; tracked here.)*
- [x] The default meeting runtime (no `--participant`, no models) is byte-for-byte unchanged
      and carries no new model/network dependency.
- [ ] The PWA installs and runs as a PWA (manifest + service worker) and connects to a
      locally running rozum (rooms list, join, post, breakout). *(co-agent-owned; tracked here.)*

## Out of scope

- The visual design / component layout of the PWA (co-agent owns `web_index.html`).
- The Seatbelt policy itself (already specified in `model-sandbox.md`).
- `busi` — its product logic is presented by the operator, not built here.
- A room-level moderator, turn scheduler, or speaker queue — **explicitly forbidden** by
  the global spec; the conference must never add one.
- Remote / multi-machine hosting, accounts, or auth beyond the existing local `Principal`
  identity — the demo runs on **one machine**.
- Audio/video — text rooms only for this demo.

## Design

```
                         ┌───────────────────────────  Seatbelt jail  ───────────────────────────┐
   PWA (.ssc → JS,       │   meeting daemon ──── rooms (.rozum/room/, disk-backed, 1 writer)      │
   installable)  ◄──────►│        ▲          ▲                                                    │
   humans join,          │        │ meeting  │ meeting.submit / read transcript                  │
   breakout, roster      │        │ protocol │                                                    │
                         │   model-participant bridge ×N  ──HTTP──►  rozum gateway ──► local model │
                         └────────────────────────────────────────────────────────────────────────┘
```

- The bridge is **just another meeting client** — this keeps the daemon's single-writer,
  no-moderator contract intact and reuses identity, transcript, and breakout for free.
- Three participants for the demo: Claude (an agent client, already supported via MCP),
  Qwen3.6 and gpt-oss (two `rozum meetings participant` processes). The gateway already
  swaps the resident model, or each participant can target its own model spec.
- The sandbox wraps the **launcher** that starts the daemon + bridges + gateway, so the
  whole conference backend shares one path-set; the PWA is a browser app (browser-sandboxed)
  that only speaks the local protocols.
- `--reply-policy mention` is the demo default so rooms stay calm and legible with several
  models present; `always` is available for lively one-on-one human↔model breakouts.

## Decisions

- **Model-participant is a meeting *client*, not a daemon feature** — chosen so the daemon's
  single-writer / no-moderator / disk-backed invariants (global spec) are untouched and the
  capability stays optional. Rejected: teaching the daemon to host models (couples the
  default runtime to inference; violates the "models optional, parallel" invariant).
- **Reply policy lives in the participant, not the room** — chosen to avoid any room-level
  moderation/turn-taking (forbidden by the global spec). A participant choosing when to speak
  is ordinary; a room ordering speakers is not. Rejected: a room speaker-queue.
- **Reuse the gateway for inference** — chosen so the bridge holds no model and benefits from
  the shared single-resident gateway + sandbox. Rejected: in-process model per participant
  (memory blow-up; duplicates the gateway).
- **PWA authored in `.ssc`** — chosen per the operator's direction and the mature ScalaScript
  JS backend already aimed at `web_index.html`. The Rust/daemon/sandbox seams are unchanged
  regardless of front-end language.

## Results

**Model-participant bridge — landed + validated live (2026-06-20).** `src/meeting/model_participant.rs`
+ `rozum meetings participant`. End-to-end proof: gpt-oss-20b joined a room, saw a human's
`@gpt-oss` message, generated a reply via the local gateway (`/v1/chat/completions`), and posted it —
**~3 s on a warm model** (cold start = model load only). Verified: roster join + room
materialization, transcript streaming, `mention`/`always`/`manual` policy (unit + live), self-skip
past the daemon's `· suffix`, peer-model loop guard, and graceful degrade (dead gateway → stays
silent, room intact). 6 unit tests; full suite 416 + 14 green; **0 panics**. `--persona` /
`--persona-file` proven to drive on-topic answers (a directive persona made gpt-oss explain rozum
concretely vs a generic deflection without one).

**Still open:** breakout one-on-one test, the Seatbelt wrap of the conference session, and the
`.ssc` → PWA front end — the co-agent's half of the split. Note for the demo: gpt-oss is a reasoning
model prone to social deflection in casual chat — a *directive* persona fixes it, and Qwen3.6 is the
snappier/steadier conversationalist; both drive through the same bridge.
